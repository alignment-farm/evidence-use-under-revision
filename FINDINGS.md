# Evidence use under revision — bounded findings, 16 September 2026

One prespecified checkpoint acquired a small, useful transfer benefit and retained
an aggregate advantage through two authoritative corrections. It did not preserve
all previously correct unchanged obligations. Further training substantially
reduced its usefulness. The fully specified executable alternative completed every
case. This bounded contribution is complete; the broader allocation and lifetime
question remains open, and root acceptance is a separate decision.

The fresh varied-history adapter at 128 updates completed 65/96 use events, versus
52/96 for the base and 61/96 for the stronger retained contextual lesson. Its
measured training plus inference time was 108.58 seconds, versus 121.16 seconds
of inference for that lesson. This is a narrow observed time payback in this
implementation, not evidence of end-to-end economic repayment. At 256 updates the
same varied-history trajectory fell to 45/96. Both checkpoints were specified
before fresh execution; the 128-update result was not a prospectively selected
winning deployment recipe. All attempted endpoints remain in the report.

Current evidence authority is the [publication-v2 ledger](evidence/publication-v2/ledger.json),
[complete fresh analysis](evidence/fresh-v1-analysis/report.json), and
[reload audit](evidence/fresh-v1-audit/report.json). The ledger checks immutable run
hashes and includes failures of useful behavior. Publication-v2 adds independent
executable-output and training-fit verification to the retained publication-v1;
it does not alter model outputs or scores.

The task combines an entity-to-plan lookup, an urgent cap replacement, three-way
allocation minimum, per-unit price, conditional surcharge, zero-allocation branch,
lane selection and leftover stock. All four output fields must be correct. Every
method receives the same authoritative current JSON policies, bindings and request,
and the same prose operations. Retrieval, authority resolution and schema discovery
are supplied. The executable interpreter is investigator-written from those
operations; it is not a learned program. Corrections change policy values and
lanes, not the operation language or schema.

Stable experience repeats 64 cases under one policy. Varied experience uses the
same requests across four policy worlds;56/64 cases have changing answers and
eight zero-allocation cases remain invariant. Each 256-record bank is available
before training. Contextual controls retain an investigator-written procedural
lesson and four fixed worked examples from the corresponding bank, with historical
values explicitly labeled. No teacher reasoning or external teacher calls are
used. A 128-update checkpoint consumes the fixed prefix of its training order;
its contextual comparator's examples come from the full available bank. Lesson
construction is supplied, not an experimentally learned summarization method.

The model is Qwen3-4B-Instruct-2507 at the hash-verified revision in
[sources/model-reference.json](sources/model-reference.json), using native MLX
LoRA on the last eight q/v projection blocks, rank 8, scale 2, direct-answer CE and
AdamW 5e-4. Exact package, weight and source provenance accompanies every run.
The implementation was adapted from the pinned sibling runtime without changing
that study or reusing its learned adapters. [Methods](notes/methods.md) records
inspected primary versions and implementations: Context-faithful Prompting
2303.11315v2, Context-Parametric Inversion 2410.10796v3 and CARE 2509.13683v1 already
narrow the question beyond generic learned counterfactual reading. Their published
results are precedents, not local reproductions.

Blocked-order development produced weak acquisition. Shuffling the exact same
256 varied records increased initial-policy performance from 17/32 to 21/32.
Initialization, data multiset and all 192 repeated control outputs matched exactly
([check](notes/order-comparison-check.json)). That prespecified diagnostic selected
shuffling for both fresh histories. The order effect is local development evidence;
the fresh experiment does not independently replicate the order contrast. The
selected 256-update varied recipe failed to improve on the fresh base, while its
prespecified 128-update checkpoint performed better.

The fresh seed 947 was reserved before model execution. It uses a new adapter
initialization, new identities and newly sampled requests. Evaluation request
amounts are outside the training request-amount set, but development and fresh
assessment use the same numerical supports. Static review found a suffix-to-plan
shortcut in development, so final fresh bindings were independently permuted before
any fresh model result. Four of eight fresh entities disagree with that suffix
rule. No exact training request enters evaluation. All methods receive these
same bindings. This is one controlled generator and one fresh initialization,
not a population estimate or natural-workflow benchmark.

There are 32 cases, half familiar entities with new requests and half fresh entities,
repeated across three policy versions: 96 use events, not 96 independent samples.
The first correction changes 11 answers; the second changes 13. Adapters stay frozen
during each correction sequence. No repair learning follows the final assessment.

training seconds for a contextual arm does not mean its construction was free.
The executable figure is measured interpreter use time with a supplied implementation.

**EU1 — limited local support.** The 128-update varied checkpoint improves initial
fresh-entity complete outcomes from 11/16 to 12/16, and independently rebound cases
from 7/8 to 8/8. Overall initial performance improves 18/32 to 21/32. Base outputs
were already valid JSON; all 96 base and 96 varied-128 generations are valid and untruncated. One of the 672
primary responses, from the stable-history lesson after correction 1, hits the
shared 48-token limit; the remaining 671 are valid JSON.
The gain therefore is not just formatting. The rebound gain is one case, and some
other components worsen: initial allocation accuracy is 24/32 versus 26/32 for the
base, while fee and lane accuracy improve. Its nonzero-allocation complete outcomes
are 13/24, 16/24 and 12/24 across versions; eight zero cases per version are easier.
The stable 256 checkpoint's initial gain 23/32 comes entirely from familiar entities
with new requests; fresh-entity accuracy remains 11/16.

**EU2 — durability occurs, but the relative history prediction is not isolated.**
Varied 128 retains advantages over the base of +3, +7, +3 complete cases across the
three versions. On the newly changed obligations it gets 7/11 and 6/13 correct.
It nevertheless loses one previously correct unchanged case at each correction:
15/16 and 14/15 are retained. The stable-history contextual lesson retains 11/11
and 14/14 of its own previously correct unchanged cases. Different starting
correct sets make those denominators important. Stable 256's advantage changes
+5, +3, -2; varied 256 has no initial advantage. No equal-update pair supplies two
clearly improved starting states for a clean comparison of retained benefits.
The history manipulation also changes policy diversity and value exposure:
correction 2's price occurs in varied training but not stable training, while the
new VIOLET lane occurs in neither. This is not a causal isolation of context
necessity from memorization or value familiarity.

**EU3 — narrow time payback, broader repayment unestablished.** Varied 128 uses
56.02 training seconds and 52.57 inference seconds over the actual 96-use sequence,
with higher aggregate complete accuracy than both contextual controls. Its 128
updates process 38,310 input positions with 1,741 loss tokens; inference uses 27,626
prompt and 1,327 completion tokens. The stronger lesson uses 111,626 prompt and 1,942
completion tokens. The adapter occupies 2,624,893 bytes. Two shared two-field policy
updates serve every arm; frozen adapters and lessons receive no maintenance updates.
These measurements do not project an unobserved longer lifetime.

The roughly 12.6-second measured advantage over the stronger lesson is sensitive
to implementation. Learned outputs are more compact, and no arm reuses a KV prefix
cache. A compact-output or cached contextual control was not tested. Investigator
construction effort, downstream error/repair cost and a deployment startup budget
are not priced; hashing, setup and audits have separate run/verification accounting.
Timings are observed local costs, not isolated hardware benchmarks. Aggregate
accuracy also hides the unchanged-case regressions. Consequently this is not a
claim of universal quality dominance or complete deployment-cost repayment. At 256
updates both learned trajectories cost about 164.8 active seconds and perform
worse than the stronger lesson. The supplied executable policy completes 96/96,
including every changed and unchanged obligation, without model learning.

Investigation totals are 1,280 updates, 1,808 generations including 80 training-fit
probes, 383,238 training input positions, 17,374 loss tokens, 941,948 generation prompt
tokens and 29,709 completion tokens. Ten saved checkpoints occupy 26,248,930 bytes.
Active update and generation time totals 1,926.77 seconds; run-reported wall time
including setup and in-run checks totals 2,216.56 seconds. Source review and
investigator development effort are additional, unpriced investigation costs. Three separate-process
audits verify 1,728 primary generations and 1,280 update token records and reproduce
198 checkpoint probes in 178.69 seconds. Audit repetitions are not accuracy samples.
The hardware is a 64 GiB Apple M1 Ultra; peak MLX allocation is below 9.62 GB against
a 32 GiB limit. Each run completed within its 30-minute cap. MLX allocation is not
full process RSS. No hardware boundary was reached and no additional hardware
was purchased.

The launch guard initially mistook its own uv parent for contention and stopped
before model loading. A first analysis attempt mis-scoped a historical request;
its correction left raw model results unchanged. Both failures and all weak
acquisitions are retained. Oracle/interpreter agreement, every-field mutation
checks, case separation, binding labels, complete scoring, file hashes, actual
parameter changes, frozen-base invariants, exact restoration and checkpoint reloads
were checked. The eight training-fit probes per checkpoint cover one familiar
entity and are diagnostic, not full training-set accuracy.
